## 개요

어떤 두 변수 x, y 사이의 관계를 찾는 일을 모델이라고 부른다.
목표는 x가 변했을 때 y가 어떻게 나올지를 예측하는 것이고,
그 관계를 수식으로 나타낸다.

## Change-point Model

BEC 관점에서는 **바깥 온도에 따른 에너지 사용량**을 모델링할 때 쓴다.
여름처럼 온도가 높을 때 에너지 소비가 올라가면 cooling shape,
겨울처럼 온도가 낮을 때 올라가면 heating shape라고 한다.

변수가 늘수록 그래프는 더 복잡해진다.
여기서 다루는 모델은 변수 다섯 개로 heating과 cooling을 함께 보는 V자형이다.

### 구현

Python의 `scipy.optimize.least_squares`로 구현할 수 있다.

```python
def energy_model(x, base, slope):
    # 모델 수식
    return x * slope + base

def residuals(x, y, params):
    # 예상과 얼마나 벗어났는지
    return energy_model(x, *params) - y

def main():
    x = ...
    y = ...
    result = least_squares(
        partial(residuals, x, y),
        ...
    )
```

## Degree Day Models

앞에서는 바깥 온도에 따른 에너지 사용량을 봤다면,
여기서는 **그날의 평균 온도**에 따른 에너지 사용량을 본다.

그리고 상황에 맞춰 앞의 Change-point Model을 써서 변수를 고른다.

## TOWT Models

특징은 다음과 같다.

1. 15분 간격으로 측정한다.
2. 온도를 균등한 구간 여섯 개로 나눠 쓴다.
3. 외부 온도는 시설이 가동될 때만 쓴다.

### 정리

인상적이었던 점은 일주일을 하나의 도메인으로 잡았다는 것이다.
직관적으로도 타당한 접근이다.
다만 그 설정을 검증하는 과정은 인용 논문에 있었을 것 같은데, 링크가 깨져 있어 확인하지 못한 점이 아쉽다.

## 결론

수식만 보면 대부분의 모델은 regression 기반이었다.
익혀 두면 좋을 것은 구현보다, 데이터를 보고 이런 모델을 어떻게 구성하게 되었는지에 대한 방법론이다.
바깥 온도인지 그날의 평균 온도인지, 요일인지 시간 슬롯인지처럼, 무엇을 기준으로 둘지가 결국 노하우가 된다.

Regression 기반 linear combination이라 모델 식 자체는 어렵지 않았다.
더 어려운 쪽은 데이터 정제와, 예측 모델을 돌릴 수 있게 만드는 변환이다.
이 라이브러리를 그대로 가져다 써도 그 수고는 사라지지 않는다.

그래서 가져다 쓰는 이득보다, 여러 추정 모델을 경험해 보는 데 더 의미가 있다고 보인다.
